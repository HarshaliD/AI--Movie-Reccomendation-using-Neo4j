# AI Movie & Employee Knowledge Graph Assistant

## 1. Project Overview

This project implements an **AI Knowledge Graph Assistant** using **Neo4j AuraDB, Python, Google Gemini, and Streamlit**. It supports two interconnected knowledge graph domains through a unified conversational interface:

1. **Movie Recommendation Domain**: Recommends movies based on shared actors and genres in Neo4j, accompanied by concise natural-language explanations generated by Gemini.
2. **Employee Knowledge Graph Domain**: Provides structured organizational insights (manager relationships, reporting hierarchies, department headcounts, multi-skill filtering, location queries, and salary threshold filters) imported directly from an Excel workbook (`data/employees.xlsx`).

A **rules-first intent router** classifies each user query into **movie**, **employee**, **general**, or **ambiguous** without invoking the LLM for routing or greetings, ensuring zero unnecessary latency and transparent decision-making.

> [!NOTE]
> **Synthetic Sample Data Notice**: All employee names, salaries, roles, and reporting relationships in `data/employees.xlsx` are entirely fictional and synthetic, designed solely to demonstrate graph relationships and querying.

---

## 2. Technology Stack

- **Neo4j AuraDB**: Cloud graph database hosting both movie and employee domains.
- **Cypher**: Parameterized graph queries identifying relationships, reporting hierarchies, and shared movie connections.
- **Python (3.10+)**: Core application logic, validation engines, and data ingestion.
- **Streamlit**: Interactive user interface with dark theme and unified query bar.
- **Google Gemini API (`gemini-3.1-flash-lite`)**: Generates explanations for movie recommendations based on graph evidence.
- **pandas & openpyxl**: Reads, validates, and processes the employee Excel workbook.
- **python-dotenv**: Secure environment configuration for database and API credentials.

## 3. Graph Data Models

### A. Movie Domain Model
The movie dataset represents cinematic relationships across three node types:

| Node | Properties | Description |
|---|---|---|
| `Movie` | `title`, `year` | Film titles in catalog |
| `Actor` | `name` | Actors cast in films |
| `Genre` | `name` | Film genre categories |

**Relationships:**
- `(Actor)-[:ACTED_IN]->(Movie)`
- `(Movie)-[:IN_GENRE]->(Genre)`

### B. Employee Domain Model
The employee dataset models an organizational hierarchy across three node types:

| Node | Properties | Description |
|---|---|---|
| `Employee` | `employee_id`, `name`, `age`, `designation`, `salary`, `location`, `joining_date` | Employee records |
| `Department` | `name` | Organizational departments |
| `Skill` | `name` | Technical & professional skills |

**Relationships:**
- `(Employee)-[:WORKS_IN]->(Department)`
- `(Employee)-[:REPORTS_TO]->(Employee)` *(Managers are employees; no separate Manager node type)*
- `(Employee)-[:HAS_SKILL]->(Skill)`

## 4. Application Architecture & Intent-Routing Flow

```text
User Question / Input
       |
       v
Normalize Input
       |
       v
Intent Router (Zero-LLM Rules-First)
       |
  +----+------------------+------------------+-------------------+
  |                       |                  |                   |
  v                       v                  v                   v
[general]            [ambiguous]          [movie]            [employee]
Greeting / Help      Clarification    Neo4j Graph        Neo4j Graph
(No DB / No LLM)     Prompt           Recommendations    Parameterized Cypher
Direct Response      Direct Prompt           |           (Lookups, Hierarchy,
                                             v           Filters, Counts)
                                      Gemini Explanation         |
                                             |                   |
  +------------------------------------------+-------------------+
  |
  v
Streamlit Unified UI Display
(Recommendation Cards, Employee Profiles, Tables, or Metrics)
```

### Intent Classification Categories:
1. **`general`**: Greetings ("Hi", "Hello"), courtesy ("thanks", "bye"), or help requests. Handled instantly without database or Gemini calls.
2. **`ambiguous`**: Underspecified inputs ("Show me the best ones", "find them") or mixed-domain questions ("Recommend movies for employees"). Displays a clarification prompt with sample queries.
3. **`movie`**: Questions referencing movies, actors, genres, or known movie titles. Executes Neo4j recommendation query and invokes Gemini for explanation.
4. **`employee`**: Organizational questions referencing employee IDs, designations, departments, managers, skills, locations, or salary thresholds. Executes parameterized Cypher queries.

> [!IMPORTANT]
> **Safety Guarantee**: Unrecognized questions never silently fall through to the movie recommendation engine; they are classified as ambiguous with guidance.

## 5. Employee Excel Workbook Structure

The synthetic dataset is located at **`data/employees.xlsx`** and contains two sheets:

### Sheet 1: `Employees` (25 Fictional Records)
- `employee_id`: Unique identifier (e.g., `EMP001` to `EMP025`).
- `name`: Fictional employee full name.
- `age`: Positive integer (24 to 52).
- `department`: Engineering, Data Science, Product, Human Resources, Finance, Marketing.
- `designation`: e.g., VP of Technology, Engineering Manager, Lead Data Scientist.
- `salary`: Synthetic annual salary in INR (₹9,50,000 to ₹45,00,000).
- `location`: Bengaluru, Hyderabad, Pune, Mumbai, Gurugram.
- `joining_date`: ISO date format (`YYYY-MM-DD`).
- `manager_id`: Valid `employee_id` of reporting manager (blank for top-level executives).
- `skills`: Comma-separated skills (e.g., "Python, SQL, Docker").

### Sheet 2: `Instructions`
Contains schema definitions, column data types, mandatory requirements, and validation constraints.

## 6. Setup and Execution

### Prerequisites
- Python 3.10 or higher
- A Neo4j AuraDB instance
- A Google Gemini API Key

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Create a `.env` file in the project root or in `movie-recommendation/`:
```env
# Neo4j AuraDB Configuration
NEO4J_URI=neo4j+s://your-instance-id.databases.neo4j.io
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your_neo4j_password
NEO4J_DATABASE=neo4j

# Google Gemini API Configuration
GEMINI_API_KEY=your_gemini_api_key
```

### 3. Import Employee Data into Neo4j
Run the automated ingestion script:
```bash
python import_employees.py
```
*What this script does:*
- Pre-validates the entire Excel workbook in memory before touching the database.
- Detects duplicate IDs, self-reporting (`EMP001` reporting to `EMP001`), and circular reporting cycles (`A -> B -> C -> A`).
- Idempotently creates uniqueness constraints and merges `Employee`, `Department`, and `Skill` nodes.
- Preserves existing movie graph data completely untouched.

### 4. Run the Streamlit Application
Launch the unified assistant web interface:
```bash
streamlit run streamlit_app.py
```

### Movie Questions:
- `"Recommend movies like 3 Idiots"`

### General & Ambiguous Interactions:

- `"Help me"` *(Displays guidance and sample questions)*
- `"Show me the best ones"` *(Prompts user to specify domain)*
- `"Recommend movies for employees"` *(Identifies mixed signals and requests clarification)*

## 8. Edge-Case and Error Handling

- **No Results Found**: Clear notices inform the user when no movies or employees match specified criteria.
- **Name Ambiguity**: When a search matches multiple individuals (e.g. searching "Sharma"), the system presents candidate profiles and prompts the user to disambiguate by employee ID.
- **Top-Level Executives**: Employees with no manager are explicitly displayed as "Top-level Executive (No reporting manager assigned)".
- **Result Truncation**: List queries are capped at 20 records to maintain responsiveness, with an explicit truncation indicator.
- **Resilience to External Failures**:
  - If Gemini API fails or times out, graph-based movie recommendations still display with a note that AI explanations are temporarily unavailable.
  - If Neo4j is offline or misconfigured, clean user-facing error messages appear without leaking credentials or stack traces.

## 10. Scope and Design Decisions

- **Deterministic Queries**: All database interactions use parameterized Cypher queries. No unrestricted natural-language-to-Cypher generation is used.
- **No Heavy Frameworks**: Built using native Python, standard libraries, Streamlit, and official drivers. No LangChain, LangGraph, vector databases, or embeddings were added.
- **Isolated Schemas**: Movie data (`Movie`, `Actor`, `Genre`) and Employee data (`Employee`, `Department`, `Skill`) reside in the same Neo4j database without collisions or destructive operations.

---

## 11. Known Limitations

- **Dataset Size**: The movie catalog and synthetic employee roster are intentionally compact to demonstrate graph modeling and query mechanics.
- **Single-Turn Queries**: Each query is evaluated independently; the assistant does not maintain persistent conversational memory or multi-turn state.
- **Heuristic Intent Extraction**: Natural language queries are parsed using maintainable rule patterns rather than probabilistic language embeddings.
