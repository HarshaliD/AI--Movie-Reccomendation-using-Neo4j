# AI Movie & Employee Knowledge Graph Assistant

## 1. Project Overview

This project implements an **AI Knowledge Graph Assistant** using **Neo4j AuraDB, Python, Google Gemini, and Streamlit**. It supports two interconnected knowledge graph domains through a unified conversational interface:

1. **Movie Recommendation Domain**: Recommends movies based on shared actors and genres in Neo4j, accompanied by concise natural-language explanations generated by Gemini.
2. **Employee Knowledge Graph Domain**: Provides structured organizational insights (manager relationships, reporting hierarchies, department headcounts, multi-skill filtering, location queries, and salary threshold filters) imported directly from an Excel workbook (`data/employees.xlsx`).

Natural language queries for employees are interpreted into a validated, structured request using an LLM (`gemini-3.1-flash-lite`) and Pydantic validation, then executed via safe, parameterized Cypher queries against Neo4j. A rules-first intent router cleanly routes between movie, employee, general, and ambiguous intents.

> [!NOTE]
> **Synthetic Sample Data Notice**: All employee names, salaries, roles, and reporting relationships in `data/employees.xlsx` are entirely fictional and synthetic, designed solely to demonstrate graph relationships and querying.

## 2. Technology Stack

- **Neo4j AuraDB**: Cloud graph database hosting both movie and employee domains.
- **Cypher**: Fully parameterized graph queries with strict allowlists for labels, properties, and operators.
- **Python (3.10+)**: Core application logic, validation engines, and data ingestion.
- **Streamlit**: Interactive user interface with dark theme and unified query bar.
- **Google Gemini API (`gemini-3.1-flash-lite`)**: Interprets natural language employee queries into structured JSON and generates movie recommendation explanations.
- **Pydantic (v2.0+)**: Strict request schema validation and normalization for operations, filters, types, and bounds.
- **pandas & openpyxl**: Reads, validates, and processes the employee Excel workbook.
- **python-dotenv**: Secure environment configuration for database and API credentials.

## 3. Graph Data Models

### A. Movie Domain Model
The movie dataset represents cinematic relationships across three node types:

| Node | Properties | Description |
|---|---|---|
| `Movie` | `title`, `year` | Film titles in catalog |
| `Actor` | `name` | Actors cast in films |
| `Genre` | `name` | Film genre categories |

**Relationships:**
- `(Actor)-[:ACTED_IN]->(Movie)`
- `(Movie)-[:IN_GENRE]->(Genre)`

### B. Employee Domain Model
The employee dataset models an organizational hierarchy across three node types:

| Node | Properties | Description |
|---|---|---|
| `Employee` | `employee_id`, `name`, `age`, `designation`, `salary`, `location`, `joining_date` | Employee records |
| `Department` | `name` | Organizational departments |
| `Skill` | `name` | Technical & professional skills |

**Relationships:**
- `(Employee)-[:WORKS_IN]->(Department)`
- `(Employee)-[:REPORTS_TO]->(Employee)` *(Managers are employees; no separate Manager node type)*
- `(Employee)-[:HAS_SKILL]->(Skill)`

## 4. Architecture & Query Pipeline

```text
User Question / Input
       │
       ▼
intent_router.py (Rules-First Intent Classification)
       │
       ├─ 'movie' ──────────► Neo4j Recommendations + Gemini Explanation
       ├─ 'general' ────────► Instant Greeting / Help (No DB / No LLM)
       ├─ 'ambiguous' ──────► Disambiguation Prompt
       └─ 'employee'
              │
              ▼
employee_interpreter.py (LLM Interpretation & Validation)
  ├── 1. Gemini structured JSON interpretation (system prompt with schema constraints)
  ├── 2. Deterministic rule-based fallback parser (for offline / malformed recovery)
  └── 3. Pydantic EmployeeQueryRequest validation
              │
              ▼
employee_queries.py (Reusable Query Execution Layer)
  ├── 1. Strict allowlists (properties, operators, sort fields)
  ├── 2. Controlled Cypher query builder with parameter binding ($p0, $p1, etc.)
  ├── 3. Unwind & distinct counting for multi-skill filtering
  ├── 4. Execution against Neo4j session
  └── 5. Grounded, evidence-based natural language summary generator
              │
              ▼
streamlit_app.py (Streamlit UI Display)
  └── Cards, DataFrames, Count Metrics, Headcounts, or Disambiguation Lists
```

## 5. Supported Operations, Fields, and Filters

### Supported Operations:
- **`count`**: Returns the total number of matching employees (e.g., *"How many employees are in Pune?"*).
- **`list`**: Lists employee records matching filter criteria (e.g., *"List Python developers in Pune"*).
- **`profile`**: Retrieves an employee's detailed profile by employee ID or name (e.g., *"Tell me about EMP001"*).
- **`get_field`**: Retrieves specific fields for an employee (e.g., *"What skills does EMP001 have?"*).
- **`manager_lookup`**: Identifies reporting managers (e.g., *"Who manages Priya?"*, *"Who is EMP001's manager?"*).
- **`direct_reports`**: Identifies direct reports under a manager (e.g., *"Who reports directly to Rahul?"*).
- **`aggregate_department`**: Aggregates employee counts across departments (e.g., *"How many employees work in each department?"*, *"Which department has the highest headcount?"*).
- **`count_and_list`**: Returns both the total count and matching records (e.g., *"How many Python developers are in Pune, and what are their names?"*).

### Supported Filter Fields:
- `location` (Pune, Bengaluru, Hyderabad, Mumbai, Gurugram)
- `department` (Engineering, Data Science, Product, Human Resources, Finance, Marketing)
- `skills` (Python, SQL, React, Docker, AWS, Kubernetes, etc.)
- `salary` (Annual INR numeric, e.g., ₹12,00,000)
- `age` (Integer age in years)
- `designation` (Job title substring)
- `employee_id` (Unique employee identifier, e.g., EMP001)
- `name` (Employee name)

### Filtering Operators & Comparisons:
- `=` (Exact match)
- `!=` (Inequality, e.g., *"Find employees who are not in Pune"*)
- `>` (Strictly greater than, e.g., *"more than 12 lakh"*, *"above 12 lakh"*)
- `>=` (Greater than or equal to, e.g., *"at least 12 lakh"*)
- `<` (Strictly less than, e.g., *"under 20 lakh"*, *"aged below 30"*)
- `<=` (Less than or equal to, e.g., *"at most 20 lakh"*)
- `between` (Bounded range, e.g., *"earning between 12 lakh and 20 lakh"*)
- `in` (Membership in list, e.g., *"in Pune or Hyderabad"*)
- `contains` (Substring match for designations and names)
- `AND` / `OR` / `NOT` (Boolean combinations with predictable semantics)

### Indian Salary Normalization:
- `12 lakh` / `12 lakhs` / `12 LPA` / `12L` = `₹1,200,000`
- `1.5 crore` / `1.5 cr` = `₹15,000,000`
- Comparison operators preserve exact boundaries (`more than 12 lakh` uses `>`, while `at least 12 lakh` uses `>=`).

## 6. Query Safety & Injection Prevention

1. **Zero String Concatenation of User Values**: All user-provided filter values are bound as Cypher parameters (`$p0`, `$p1`, `$req_skills`).
2. **Explicit Allowlists**: Only allowed properties (`e.name`, `e.salary`, `d.name`, etc.) and allowed sort fields can be referenced in Cypher queries.
3. **Pydantic Validation**: All requests are parsed into `EmployeeQueryRequest` before query construction. Unsupported fields or operators are rejected during validation.
4. **Duplicate Prevention**: Multi-skill matches and relationship traversals use `DISTINCT` aggregations to prevent Cartesian duplication in query results.
5. **Known Bug Fix**: Queries such as *"How many employees have location as Pune?"* are parsed into a location count query returning the exact count for Pune, resolving the legacy bug where total department headcounts were returned instead.

## 7. Setup and Execution

### Prerequisites
- Python 3.10 or higher
- A Neo4j AuraDB instance
- A Google Gemini API Key

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Create a `.env` file in the project root or in `movie-recommendation/`:
```env
# Neo4j AuraDB Configuration
NEO4J_URI=neo4j+s://your-instance-id.databases.neo4j.io
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=your_neo4j_password
NEO4J_DATABASE=neo4j

# Google Gemini API Configuration
GEMINI_API_KEY=your_gemini_api_key
```

### 3. Import Employee Data into Neo4j
Run the automated ingestion script:
```bash
python import_employees.py
```
*What this script does:*
- Pre-validates the entire Excel workbook in memory before touching the database.
- Detects duplicate IDs, self-reporting (`EMP001` reporting to `EMP001`), and circular reporting cycles (`A -> B -> C -> A`).
- Idempotently creates uniqueness constraints and merges `Employee`, `Department`, and `Skill` nodes.
- Preserves existing movie graph data completely untouched.

### 4. Run the Streamlit Application
Launch the unified assistant web interface:
```bash
streamlit run streamlit_app.py
```

## 10. Scope and Design Decisions

- **Deterministic Queries**: All database interactions use parameterized Cypher queries. The LLM produces structured JSON matching a strict Pydantic schema, not arbitrary Cypher strings.
- **No Heavy Frameworks**: Built using native Python, standard libraries, Streamlit, and official drivers. No LangChain, LangGraph, or unnecessary abstractions were added.
- **Isolated Schemas**: Movie data (`Movie`, `Actor`, `Genre`) and Employee data (`Employee`, `Department`, `Skill`) reside in the same Neo4j database without collisions or destructive operations.

---

## 11. Known Limitations

- **Dataset Size**: The movie catalog and synthetic employee roster are intentionally compact to demonstrate graph modeling and query mechanics.
- **Single-Turn Queries**: Each query is evaluated independently; the assistant does not maintain multi-turn conversational context.
- **Fixed Schema**: Queries are restricted to the entities and properties present in the knowledge graph schema (`Employee`, `Department`, `Skill`).
